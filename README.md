# Jogo-IP
Projeto final da disciplina de Introdução a programação do centro de informática (Cin).
Projetos IP
O projeto das disciplinas de Introdução à Programação é uma oportunidade de integrar, a
partir de esforço direcionado e com um resultado focado, os conteúdos vistos durante o
semestre. Além disso, proporciona a valiosa experiência de trabalhar em grupo, resolvendo
problemas de maneira colaborativa.
⚠️ Vocês terão que preencher várias informações em uma planilha desde o início do
projeto até a conclusão. No texto abaixo, vocês encontrarão informações específicas sobre
tal preenchimento. Os links para as planilhas são:
* Planilha CC/IA
* Planilha EC
* Planilha SI

# Tema
Nesta edição, foi estabelecido um tema orientador que permitirá à equipe trabalhar com o
conceito de Orientação a Objetos. Os requisitos são simples, porém devem ser
implementados obrigatoriamente.
Requisitos Mínimos: O grupo será responsável por criar um sistema interativo
em um ambiente 2D, no qual o usuário controla um objeto com a finalidade de coletar
outros objetos dispostos na tela. Deverão ser incluídos no mínimo três tipos distintos de
objetos coletáveis. O sistema deverá manter um registro da quantidade de
objetos coletados para cada tipo e exibirá essas informações ao usuário. Além disso,
o projeto deverá ser estruturado com base na Orientação a Objetos.
Tradicionalmente, as equipes têm usado o PyGame.

# Desenvolvimento
* O projeto deverá ser desenvolvido exclusivamente usando a linguagem de
programação Python.
* Os grupos deverão pesquisar ferramentas, frameworks e bibliotecas mais
adequados ao tema escolhido e integrá-los na solução final. O uso de cada
elemento escolhido deverá ser justificado no relatório final.
* O projeto deve ser implementado em grupo, respeitando o limite de 5 a 6
integrantes.

* Grupos poderão ter integrantes a mais apenas com autorização de um dos
professores. Equipes com 5 integrantes poderão receber um integrante
adicional se for necessário conseguir um grupo para um aluno.
Eventualmente, isto também pode acontecer com equipes com 6 integrantes.
* As informações de cada grupo deverão ser registradas na planilha, na aba “Equipes”
(olhar início deste documento)

# Acompanhamentos e Checkpoints
No horário das aulas definidas no cronograma da disciplina, serão feitos checkpoints
(presenciais e remotos no discord).
Nos checkpoints, todos os membros da equipe devem estar presentes.
Antes de cada checkpoint, cada grupo deve atualizar a planilha, na aba
“Checkpoints” (olhar o início deste documento), sobre o que foi feito desde o último
checkpoint, os próximos passos e as dificuldades encontradas.
Os grupos que não responderem às questões na planilha e/ou não participarem do
checkpoint presencial serão penalizados no critério “Evolução e Desenvolvimento do
Projeto”.

# Apresentação
* A apresentação dos projetos ocorrerá de forma presencial, na data e no
horário marcados no cronograma da disciplina.
* Todos os membros do grupo devem apresentar.
* Os grupos deverão elaborar um documento no Google Slides (ou equivalente) para
a apresentação.
* Os tópicos da apresentação devem seguir os tópicos do relatório, porém,
apresentados de forma sucinta como slides.
* O template disponibilizado através deste link deve ser utilizado para a criação da
apresentação (cada grupo pode formatar os slides da maneira que desejar, contando que os
tópicos abordados sejam os exigidos).
* O sistema deve ser executado durante a apresentação para demonstrar seu
funcionamento.
* A duração da apresentação de cada grupo deverá ser de, no máximo, 8 minutos.

# Entregas
Para realização da entrega, os grupos deverão preencher a planilha com os links 
* 1) do repositório github (uso obrigatório), 
* 2) do relatório
* 3) da apresentação de slides, até a data da apresentação. Após o deadline, a edição das planilhas serão desabilitadas,
então, não se atrasem.
## 1) Repositório github com código-fonte
* Código fonte do projeto com:
* Instruções de como o projeto deve ser rodado;
* Capturas de tela do sistema funcionando para compor a galeria de projetos

## 2) Relatório
O relatório deve ser entregue em PDF ou no próprio README.md do repositório (caso seja
usado o github) e deverá conter os seguintes pontos:
* Título do projeto e membros da equipe;
* A descrição da arquitetura do projeto, explicando como o código foi organizado;
* As capturas de tela do sistema funcionando para compor a galeria de projetos
* As ferramentas, bibliotecas, frameworks utilizados com as respectivas
justificativas para o uso;
* A divisão de trabalho dentro do grupo (quem fez o quê);
* Os conceitos que foram apresentados durante a disciplina e utilizados no projeto
(indicando onde foram usados);
* Os desafios e erros enfrentados no decorrer do projeto e as lições aprendidas.
Para tanto, respondam às seguintes perguntas:
* Qual foi o maior erro cometido durante o projeto? Como vocês lidaram com
ele?
* Qual foi o maior desafio enfrentado durante o projeto? Como vocês lidaram
com ele?
* Quais as lições aprendidas durante o projeto?

## 3) Slides da apresentação
Os slides da apresentação deverão ser compartilhados com os professores.

Avaliação e Pontuação
A avaliação do projeto levará em conta:
* O processo de desenvolvimento e evolução do projeto;
* O funcionamento e a qualidade do software final;

* A entrega e a qualidade do relatório;
* A organização e qualidade da apresentação.
Como combinado no início do período, o projeto é obrigatório e equivale a 34% da nota da
disciplina.
